## 0. Before you start

Read `DEPENDENCY_AND_DOWNLOAD_REPORT.md` first. It lists every download and its size (~1.9–2.1 GB total, ~5.5–6 GB on disk) and the two risks worth weighing — chiefly that your laptop's TLS truncated a 100 MB download today, and Android Studio is twelve times that.

## 1. Install Android Studio

1. Download Android Studio (Ladybug 2024.2.1 or later) from `developer.android.com/studio`.
2. Install **to your user profile**, not Program Files — that avoids needing administrator rights.
3. On first launch, let the Setup Wizard install **SDK Platform 34** and **Build-Tools 34.x**.

The bundled JetBrains Runtime 17 is sufficient; no separate JDK is needed.

If the download truncates, Android Studio's downloader resumes — restart it rather than beginning again.

## 2. Put the model in place — required, the build will not work without it

The trained model is **deliberately excluded** from this source tree. It is 8.9 MB, and the Phase 1 archive is the single authoritative copy; duplicating a binary artifact invites the two to drift apart silently.

Copy it to exactly this path:

```
from:  C:\Users\VIGNESH\Documents\AGRI_SHIELD_AI\models\agrishield_tomato4.pte
to:    android_app\app\src\main\assets\agrishield_tomato4.pte
```

The filename must match exactly — `Classifier.ASSET_NAME` looks for `agrishield_tomato4.pte`. The folder already contains `MODEL_GOES_HERE.txt` as a reminder; you can leave it there.

At startup the app copies the asset to internal storage, computes its SHA-256, and **refuses to run on mismatch**:

```
f57f5ec391f44b8add7fee57cd47e439e0ad17aaec5ce5d3e8aeaf1601037f4b
```

If the model is missing you will get a clear error naming this file, not a crash.

## 3. Gradle wrapper — included and checksum-verified

`gradlew`, `gradlew.bat` and `gradle/wrapper/gradle-wrapper.jar` are all included. They are the **official** files, generated by Gradle's own `wrapper` task (Gradle 8.14.3, run offline) — not hand-written.

The JAR's SHA-256 is:

```
7d3a4ac4de1c32b59bc6a4eb8ecb8e612ccd0cf1ae1e99f66902da64df296172
```

which is **exactly** the "Wrapper JAR Checksum" Gradle publishes for 8.14.3 at `gradle.org/release-checksums`. You can confirm it yourself:

```
certutil -hashfile android_app\gradle\wrapper\gradle-wrapper.jar SHA256
```

**Why an 8.14.3 wrapper for an 8.9 build:** the wrapper JAR is only a bootstrapper. It reads `gradle-wrapper.properties`, which names **Gradle 8.9**, downloads that distribution (~130 MB) on first run, and hands over to it. Wrapper and distribution versions are independent; this is the normal arrangement.

The earlier `init_gradle_wrapper.bat` and its README are removed — they existed only because the JAR was missing.

### If the 130 MB Gradle download is a problem

Your laptop's TLS has truncated large downloads. If the wrapper's first-run download of Gradle 8.9 fails repeatedly, Android Studio can build without it:

1. **File → Settings → Build, Execution, Deployment → Build Tools → Gradle**.
2. Set **Use Gradle from:** to *Specified location*, pointing at a Gradle 8.9+ installation, or the distribution Android Studio has already downloaded.
3. Sync, then **Build → Build APK(s)**.

## 3.1 Build

Command line, from `android_app`:

```
gradlew.bat assembleDebug
```

Or in Android Studio: **Build → Build Bundle(s) / APK(s) → Build APK(s)**.

The debug APK lands at:

```
android_app/app/build/outputs/apk/debug/app-debug.apk
```

The first build downloads Gradle 8.9 (~130 MB) and the dependencies (~25–40 MB). Nothing here has been run yet — no Android SDK is reachable from the environment the project was prepared in.

## 4. Run the tests

**JVM unit tests** — no device needed:

```
gradlew.bat test
```

31 tests in four classes. All 31 were compiled and run with JUnit 4.13.2 on OpenJDK 21 while preparing this project, and all pass — but **not through Gradle**, which needs the Android plugin. Expect the same result from `gradlew test`; if it differs, that difference is itself worth reporting.

| Class | Tests | Covers |
|---|---|---|
| `PreprocessUnitTest` | 8 | tensor shape, class order, `Resize(109)`, ImageNet constants, aspect, **banker's-rounding crop** (the `Math.rint` fix — must not regress) |
| `OrientedRgbTest` | 6 | all 8 EXIF orientations against Pillow-derived permutations, alpha dropped, retained-area fractions against torchvision, array-limit guard |
| `MemoryPlanTest` | 8 | itemised plan for 12 MP, rotated portraits, refusal on small heap / low native memory / 108 MP capture / array overflow, coverage of measured JVM peaks |
| `InferenceGuardTest` | 9 | close-during-forward deferral, exactly-once release under 400 concurrent closes, serialised forward, 200 randomised interleavings, late-arriving model released |

**Instrumented tests** — phone attached, USB debugging on:

```
gradlew.bat connectedAndroidTest
```

These check that the model asset is authentic, that it loads and returns four logits summing to 1, and — the one that actually matters — **decoder parity**: Android's JPEG decoder against Pillow's on the same file.

Pull the result:

```
phase2\platform-tools\adb.exe pull /sdcard/Android/data/org.agrishield.ai/files/decoder_parity.json
```

## 6. Verify offline operation

The app declares **no `INTERNET` permission**. It cannot open a socket, so offline operation is enforced by Android rather than asserted by us. To demonstrate:

1. Enable airplane mode.
2. Select or capture a leaf photograph.
3. Run detection.

You can confirm the absence of the permission independently:

```
phase2\platform-tools\adb.exe shell dumpsys package org.agrishield.ai | findstr INTERNET
```

Expect no output.
